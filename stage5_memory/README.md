# 第 5 关 · 会话记忆与上下文管理

**时长**：2 个晚上 ｜ **难度**：中等 ｜ **对标真项目**：Agent 会话态 / Chat 历史存储

## 本关目标

解决两个真实问题：采购员问久了爆上下文窗口；重启程序就全忘。
理解"记忆全是工程手段，模型本身过目即忘"。

## 动手任务

### 任务 1：上下文压缩（一晚）

给 harness 加检查：每轮请求前估算 messages 总长度，超过阈值（比如 8000 字符）时：
1. 取出最早的 60% 对话历史
2. 调 `call_model` 让模型"把以下对话总结成要点，保留关键事实、结论和未完成事项"
3. 用一条"【早前对话摘要】…"替换掉那 60%

测试：连续问 20 轮不同采购问题（查供应商、问制度、聊某个项目），观察压缩触发，
再问早期细节，看摘要保住了多少信息。（Cursor 处理长对话就是这么做的。）

### 任务 2：长期记忆（一晚）

1. 约定一个 `memory.md`，启动时若存在则注入 system prompt
2. 注册工具 `remember(fact)`：把一条事实追加写入 memory.md
3. system prompt 指导："当用户告诉你其身份、所属单位、常用采购品类等信息时，主动 remember"

**验收实验**：告诉它"我是设备部的采购员老王，主要负责高压开关类采购"，
退出重启，问"我是谁、我平时管什么采购"——必须答对。
（这正对标真项目：智能体要记住当前采购员的角色和单位，才能做后面的权限过滤。）

### 任务 3（选做）：记忆检索化

memory.md 无限增长也会爆。改成 JSONL（每条一行），启动只注入最近 10 条 +
提供 `search_memory(query)` 按关键词查旧记忆。这就是长期记忆从"全量加载"走向"检索加载"，
和第 6 关 RAG 是同一个思想。

## 验收标准

- [ ] 20 轮长对话不爆窗口，压缩后仍能回忆早期要点
- [ ] 跨会话记忆实验通过

## 思考题

1. 压缩摘要会丢信息，采购场景里什么信息最不能丢？（金额？供应商名？结论？）怎么在压缩 prompt 里保护它们？
2. 短期记忆、长期记忆、RAG 知识库，三者边界在哪？
3. 多个采购员共用一个智能体时，记忆怎么隔离？（直接引出第 8 关的权限/数据隔离）
