# 第 4 关 ⭐ · 提示词与技能管理（Skills）

**时长**：2 个晚上 ｜ **难度**：核心 ｜ **对标真项目**：提示词管理 / 业务提示词

## 本关目标

实现主流的技能包机制（对标 Anthropic/Cursor 的 Agent Skills，也对标方案里的"提示词管理模块"），
理解"渐进式披露"这一上下文工程的核心思想。

## Skill 和 Tool 的区别（先想明白再动手）

- **Tool 给能力**：查供应商库、调征信接口——agent 多了一双手（第 2、7 关）
- **Skill 给知识和流程**：一份"什么情况下用、具体步骤怎么做"的说明书——agent 多了一份经验

比如"怎么写一份合规的单一来源申请理由"——这不是一个函数，而是一套**写作流程和要点**，
适合做成 skill。真项目里采购业务的各种"业务提示词模板"，本质就是 skill。

核心机制是**按需加载**：平时只有名称+描述占上下文（几十 token），用到时才把全文读进来。

## 动手任务

### 任务 1：设计技能目录规范（半晚）

```
stage4_skills/skills/
├── single-source-reason/        # 单一来源理由撰写
│   └── SKILL.md
└── supplier-background-check/    # 供应商背调要点
    └── SKILL.md
```

SKILL.md 格式（frontmatter + 正文）：

```markdown
---
name: single-source-reason
description: 需要撰写或审核"单一来源采购申请理由"时使用
---

# 单一来源理由撰写技能

撰写时遵循以下步骤：
1. 先确认采购金额，判断是否触发专家论证门槛（可让我去检索《单一来源采购管理办法》）
2. 申请理由必须包含四要素：采购标的、唯一性论证、价格合理性说明、不可替代性依据
3. 避免使用被明确禁止的理由（如"供应商报价低""关系稳定""采购人未提前规划"）
4. 输出结构化的申请理由草稿，并在末尾标注引用了哪条制度
...
```

### 任务 2：接入 harness（一晚）

1. 启动时扫描 `skills/`，解析所有 frontmatter
2. 把技能清单（仅 name + description）注入 system prompt："你有以下技能，判断相关时先调用 load_skill 加载"
3. 注册工具 `load_skill(name)`：返回对应 SKILL.md 全文

### 任务 3：写两个真技能并验证（一晚）

1. **single-source-reason**：内容见上。测试："帮我写一份 120 万元采购某专利检测设备的单一来源申请理由"，观察它先 load_skill、再（可能）想去查制度、最后按四要素产出
2. **supplier-background-check**：写清"背调要核查哪些字段、缺哪些算不完整、命中涉诉名单怎么处理"。测试："帮我看看 S008 的背调够不够入库标准"

对照实验：把技能系统关掉再问同样问题，对比回答质量——这就是 skill 的价值展示，也是你将来给客户演示"提示词管理"的现成案例。

## 验收标准

- [ ] 新增技能 = 新建文件夹放一个 SKILL.md，代码零改动
- [ ] agent 面对相关问题会自主加载对应技能，无关问题不加载
- [ ] 能说清 skill / tool / system prompt 三者的分工
