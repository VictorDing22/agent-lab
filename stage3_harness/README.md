# 第 3 关 ⭐ · Harness + MaaS 模型网关

**时长**：3 个晚上 ｜ **难度**：核心 ｜ **对标真项目**：MaaS / 模型网关（方案头号重点）

## 本关目标

两件事：
1. 把第 2 关的脚本升级成可扩展的 **harness**（对标"智能体定制平台"）；
2. 单独抽出一个 **模型网关（MaaS）** 模块——这是西高院方案里反复强调、花最多篇幅的东西。

学完你就懂：为什么方案说"业务系统不要直连千问，一律走网关"。

## 什么是 MaaS / 模型网关

真项目里有千问、DeepSeek、Embedding、ReRank、OCR、多模态一堆模型。
如果每个业务模块自己直连各模型，会乱成一锅粥。MaaS 网关是**所有模型调用的唯一入口**，统一负责：

- **模型路由**：简单问答走小模型，复杂分析走大模型，检索走 embedding
- **限流 / 熔断**：防止 OCR 批处理把在线问答的资源抢光
- **超时重试**：某次调用失败自动重试或降级
- **调用日志 / 用量统计**：谁、什么时候、调了哪个模型、花了多少 token
- **返回格式规范化**：屏蔽不同模型的协议差异

你这一关就写一个**迷你版网关**，把这些能力都体验一遍（规模小，但机制真）。

## 动手任务

### 任务 1：模型网关模块（一晚）

写一个 `gateway.py`，对外只暴露一个函数（业务代码只准调它，不准直接 new OpenAI）：

```python
def call_model(task_type: str, messages: list, **opts) -> dict:
    """统一模型入口。
    task_type: 'chat'(在线问答) / 'analyze'(复杂分析) / 'embed'(向量化)
    根据 task_type 路由到不同模型；统一做重试、限流、日志、用量统计。"""
```

要做到：
- **路由**：`chat` → qwen3:8b；`analyze` → 也可先用同一个模型但走不同参数（temperature 更低）；`embed` → bge-m3。真项目这里就是"chat 路由千问、analyze 路由 DeepSeek、embed 路由 Embedding 模型"
- **重试**：调用失败重试 2 次，仍失败返回友好错误
- **限流**：简单实现——同一 task_type 每秒最多 N 次（体会"OCR 别抢在线问答资源"）
- **日志**：每次调用写一行到 `gateway_log.jsonl`：时间、task_type、模型、耗时、token 估算

### 任务 2：工具注册器（一晚）

让"写一个带 docstring 的函数 + 装饰器"就自动注册成工具：

```python
@tool
def get_supplier_detail(supplier_id: str) -> str:
    """按供应商ID返回详细信息。supplier_id: 供应商编号，如 S001"""
    ...
```

装饰器用 `inspect.signature()` 读签名和类型注解，自动生成 JSON Schema，存进全局 `TOOLS`。
把第 2 关三个供应商工具改成装饰器注册。

### 任务 3：护栏 + 事后回放（一晚）

1. **步数上限** `max_steps=15`，超限强制模型"根据已有信息给最终答案"
2. **异常自愈**：工具抛异常不崩溃，把 `f"工具出错: {e}"` 回填让模型自我修正
3. **Tracing**：每步写 `traces/时间戳.jsonl`（step、工具、参数、结果预览、耗时），再写个 `replay.py` 人类可读地打印某次运行
