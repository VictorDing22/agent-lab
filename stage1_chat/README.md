# 第 1 关 · 采购智能助手雏形

**时长**：半天 ｜ **难度**：入门 ｜ **对标真项目**：采购智能助手

## 本关目标

读懂 LLM API 的原始形态：messages 数组、角色、流式输出、上下文窗口。
破除"模型记得我说过什么"的错觉。做出一个能多轮对话的"采购助手"命令行。

## 前置条件

完成第 0 关环境准备（Ollama 已启动，`qwen3:8b` 已拉取）。

## 动手任务

### 任务 1：跑通起步代码（15 分钟）

```bash
cd agent-lab
uv sync
uv run python stage1_chat/chat.py
```

它已经带了一个"采购助手"的 system prompt。问它几个采购相关问题（比如"单一来源采购是什么意思"），
确认流式输出正常。输入 `/quit` 退出。

> 注意：这一关它只会凭模型自己的知识回答，**还不能查你的供应商库和制度**——
> 那是第 2、6 关的事。现在先理解对话本身。

### 任务 2：逐行读懂 chat.py（1 小时）

搞懂三个问题（读代码 + 问 Cursor，直到能自己讲出来）：

1. `messages` 里 system / user / assistant 三种角色各起什么作用？
2. 为什么每次请求都要把**整个** `messages` 历史发过去？（动手试：改成只发最后一条 user 消息，观察它"失忆"）
3. 流式输出的 chunk 是什么结构？



### 任务 3：三个改造练习（2 小时）

> 三个改造已写进 `chat.py`。可交互体验，也可用自检一次验证：
> `uv run python stage1_chat/chat.py --selftest`

1. **加** `/system` **命令**：运行中输入 `/system 你是严格的采购合规审核员` 可热替换 system prompt，观察语气立刻变化
2. **加 token 估算**：每轮回答后打印本次大约消耗多少字符/token（粗略按 字符数÷1.5），观察它随轮数增长——这就是"上下文被吃掉"，对标真项目里要控制的 token 预算
3. **加** `/save` **与** `/load`：把当前对话历史存成 JSON，重启可恢复——你已经摸到"会话态/Chat 历史"的本质（第 5 关深入）



## 验收标准

- [ ] 能不看代码，口头解释"模型为什么显得有记忆"
- [ ] 三个改造练习都能演示



## 思考题（写进 notes.md）

1. 采购员连续问 500 轮，会发生什么问题？你能想到几种解决办法？（联系真项目的会话态管理）
2. 同样一句"回答要引用制度条款"，写在 system prompt 里 vs 写在 user 消息里，效果一样吗？做实验验证。



## 常见坑

- Ollama 没启动会报连接拒绝：`brew services start ollama`
- 第一次请求慢是模型在载入内存，正常
- qwen3 可能输出 `<think>...</think>` 思考段，先不用管，第 2 关会处理
