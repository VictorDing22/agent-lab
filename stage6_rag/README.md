# 第 6 关 ⭐ · 制度知识库 RAG

**时长**：一个周末 ｜ **难度**：核心（客户项目直接相关）
**对标真项目**：知识库模块 + RAG 检索策略 + 答案可追溯 + ReRank + Embedding

## 本关目标

亲手搭一条完整 RAG 链路：解析 → 切分 → 向量化 → 混合检索 →（可选 ReRank）→ 带条款出处回答。
这是西高院方案里"单一来源智能审核""采购制度问答"的技术地基，这一关踩的坑都是提前替真项目踩的。

## 语料

用 `采购数据/制度/` 下三份制度（都带 frontmatter 元数据：制度版本、生效日期、业务类型）：
- 单一来源采购管理办法.md
- 供应商准入管理办法.md
- 采购管理办法.md

## 动手任务

### 任务 1：加载与切分（半天）

写 `ingest.py`：
1. 读取三份 md，解析出 frontmatter 元数据
2. **按"条"切分**（第X条 是天然的切分边界），每块保留元数据 `{制度名, 版本, 生效日期, 条号}`
3. 打印看 20 个块，**肉眼检查切分质量**——这个习惯比任何技巧都值钱

> 为什么按条切：采购制度问答要精确定位到"第几条"，切太碎会拆散条款，切太大会稀释相关性。

### 任务 2：向量化入库（半天）

1. 通过第 3 关的 `call_model(task_type='embed', ...)` 调 bge-m3，把每块变成向量
2. 存 SQLite：`(id, 制度名, 条号, 生效日期, text, embedding_json)`。几十个块全量算余弦相似度毫秒级
3. 写 `search_vector(query, top_k=5)`

### 任务 3：混合检索（半天，本关精华）

先只用向量检索搜这几个查询，你大概率发现精确词条搜不准：
- **"50万"**（数字）
- **"专家论证"**（专有词）
- **"失信被执行人能不能准入"**

再加关键词通道（SQLite `LIKE` 或 FTS5），最终得分 = 向量相似度 + 关键词命中 加权融合。
对比前后效果，把结论写进 notes.md——**这个实验结论可以直接写进你给客户的方案**
（"为什么采购场景必须混合检索，不能纯向量"）。

### 任务 4（选做）：ReRank

方案里说 ReRank 一期可不上、先预留接口。你也照这个思路：
先跑通"混合检索 + 千问生成"，把接口留出来。有兴趣再用一个小 rerank 模型或让 LLM 对
候选片段打分排序，对比命中质量提升。**体会"什么时候才值得上 ReRank"。**

### 任务 5：接入 agent + 可追溯（半天）

1. 把检索注册为工具 `search_policy(query)`，返回 top 片段（带制度名+条号）
2. system prompt 要求：**回答必须基于检索结果，标注"依据《X办法》第X条"；检索不到就明说，禁止编造**
3. 验证问题：
   - "单一来源采购超过多少钱需要专家论证？"（应答：50万元及以上，依据《单一来源采购管理办法》第五条）
   - "失信被执行人能不能准入？"（依据《供应商准入管理办法》第二条）
   - "预算300万的设备应该用什么采购方式？"（依据《采购管理办法》第二条）
   - "采购能不能拆成小单避免招标？"（应答：不能，依据相关条款）
   - "报销流程是什么？"（语料里没有——看它会不会诚实说没有，不编造）

## 验收标准

- [ ] 五个验证问题全部通过，条款出处正确，没有的内容不编造
- [ ] 完成混合检索对照实验并有记录

## 思考题

1. 制度块切太大/太小各有什么问题？在这三份制度上实际表现如何？
2. 采购员问"上面那条超过多少钱要论证"（指代上一轮），直接拿这句去检索会怎样？怎么解决？（查询改写）
3. 真项目的制度是 Word/PDF/扫描件而非干净 md，链路上要多哪些环节？哪个环节最可能成为效果瓶颈？（引出 OCR、数据治理）
4. 制度有多版本、带生效日期，怎么保证不召回过期制度？（元数据过滤——真项目的硬要求）
