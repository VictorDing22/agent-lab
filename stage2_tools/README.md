## 本关目标

不用任何框架，亲手实现 tool calling + ReAct 循环，让采购助手能**真正查到你的供应商库**。
写完这关你就明白：所有 agent 框架（Dify、Coze、CoMi Builder、LangChain）底层都在干同一件事。

## 前置阅读

- Anthropic《Building effective agents》（重点读 "Agents" 一节）
- ReAct 一张图就够：Thought（想）→ Action（调工具）→ Observation（看结果）→ 循环

## 原理速览

模型**不执行任何代码**。tool calling 是三步协议：
1. 你在请求里声明可用工具（名称、描述、参数 JSON Schema）
2. 模型回复里若含 `tool_calls`，意思是"请帮我执行这个函数，参数是这些"
3. **你的代码**执行函数，把结果作为 `role:"tool"` 的消息追加进 messages，再次请求模型

Agent 循环 = 把这三步套进 while，直到模型不再请求工具（给出最终答案）。

## 动手任务

### 任务 1：先写工具函数（半天）

在 `供应商.json` 之上写三个纯 Python 函数（先不接模型，命令行直接调通）：

```python
def search_suppliers(category: str = "", keyword: str = "") -> str:
    """按品类或关键词搜索供应商，返回匹配到的供应商名称与ID列表。
    category: 采购品类，如 '高压开关'、'电线电缆'；keyword: 供应商名称关键词。"""

def list_suppliers() -> str:
    """列出供应商库里所有供应商的ID和名称。"""

def get_supplier_detail(supplier_id: str) -> str:
    """按供应商ID返回其详细信息：资质、注册资金、历史项目、风险状态等。"""
```

### 任务 2：单次工具调用（半天）

把三个工具声明给模型，问"库里有哪些供应商"。
打印**完整的原始请求和响应 JSON**，亲眼看到 `tool_calls` 字段长什么样。这一步目的是看清协议。

### 任务 3：完整 Agent 循环（半天）

套进 while 循环。每步打印：模型想调什么工具、参数、返回了什么（前 200 字符）。
测试问题：
- **"帮我找能供高压开关的供应商，并告诉我哪家历史合作评价最好"**
  观察它自己走 `search_suppliers("高压开关")` → 对结果里几家分别 `get_supplier_detail` → 比较 → 总结。
- **"S005 这家供应商靠谱吗？"** 看它调 detail 后怎么解读 risk_status。

没有任何代码写死这个顺序——这就是 agent 的"自主规划"。

### 任务 4：刻意破坏实验（2 小时，本关精华）

2. 让它查一个不存在的 ID（如 S999），把异常文本原样回填，看它会不会自我修正
3. 去掉循环步数上限，想一个可能让它反复调工具的问题，理解为什么生产必须有护栏
